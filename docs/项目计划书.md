# pgx-rag 项目计划书（供评审）

> 版本：v1（2026-11-10）· 状态：阶段 1 完成、阶段 2 进行中
> 一句话：**把「药物说明书原文」和「CPIC 基因用药指南」两个公开数据集，做成给临床药师/医生用的、每一句都能回溯到原文的用药证据卡。**

---

## 1. 项目定位

### 1.1 做什么

面向**专业侧**（临床药师、开方医生、医院信息科）的**证据核验工具**：输入「药 + 患者基因型/表型（+ 临床场景）」，输出一张结构化证据卡：

1. **指南侧**：CPIC 推荐原文 + 推荐强度（Strong / Moderate / Optional）+ 是否建议先做检测；
2. **说明书侧**：FDA 标签相关段落原文 + 章节 + 生效日期 + set_id（可回溯到 DailyMed）；
3. **一致性判定**：一致 / 指南更严格 / 说明书更保守 / 存在明显差异 / 说明书未收录该基因。

### 1.2 为什么不是「患者问答机器人」

| 维度 | 患者侧（本期不做） | 专业侧（本期做） |
|---|---|---|
| 用户 | 拿到基因检测报告的患者 | 药师/医生/信息科 |
| 输入 | 报告片段、过敏史 | 药 + 表型 + 适应症场景 |
| 输出 | 通俗解释 + 就医引导 | 可引用的证据卡 + 可导出规则 |
| 风险 | 高（易被当成医疗建议） | 可控（使用者有专业判断力） |
| 可验证性 | 需要药师盲评 | **可与 CPIC 官方推荐逐条对照** |

选择专业侧的核心原因：**它的「正确答案」是公开的、可逐条核对的**，不依赖评审人的医学直觉。

### 1.3 明确不做

- 不做诊断、不替代医生决策；
- 不给患者「能不能吃/该吃多少」的个体化结论；
- 不做「无依据也能编出答案」的自由发挥（证据不足必须显式标注）。

## 2. 数据集

### 2.1 数据集 A：FDA 药品说明书（SPL）

| 项 | 内容 |
|---|---|
| 来源 | OpenFDA `https://api.fda.gov/drug/label.json` |
| 本质 | FDA 批准的处方信息（SPL 格式，原为 XML，OpenFDA 提供 HTML 化 JSON） |
| 覆盖 | 17 个 CPIC 药物（氯吡格雷、华法林、他克莫司、可待因、曲马多、辛伐他汀、硫唑嘌呤、别嘌醇、卡马西平、阿巴卡韦、伏立康唑、塞来昔布、昂丹司琼、泮托拉唑、艾司西酞普兰、卡培他滨、苯妥英） |
| 规模 | **2416 条切片**（正文 1981 / 表格 435）+ **178 张表格**（1844 数据行） |
| 关键字段 | `boxed_warning`、`dosage_and_administration`、`contraindications`、`clinical_pharmacology`、`drug_interactions`、`*_table`（HTML 表格） |
| 交叉核对 | DailyMed SPL API 核对 setid / 标题 / 发布日期（17 个中 15 个 setid 一致） |
| 授权 | 美国政府公开数据，可自由使用 |

**实测结论（重要）**：17 个药里 **15 个**说明书收录了目标基因；**2 个没有**——辛伐他汀的 SLCO1B1（50 个候选标签 0 命中）、华法林的 CYP4F2。这是必须引入第二个数据集的直接原因。

### 2.2 数据集 B：CPIC 基因-药物指南

| 项 | 内容 |
|---|---|
| 来源 | CPIC 官方 API `https://api.cpicpgx.org/v1`（PostgREST，返回 JSON） |
| 覆盖 | 全库 635 个基因-药对；收敛到本项目 17 个药：**50 个基因-药对、247 条按表型的推荐** |
| 推荐强度分布 | Strong 141 / Moderate 56 / Optional 22 / 无推荐 24 / n/a 4 |
| 关键表 | `pair`（CPIC 等级 A–D、检测建议 Testing Required / Actionable PGx）、`recommendation`（表型 × 临床场景 → 推荐原文 + 强度）、`gene_result`（表型解读 + EHR 风险优先级，70 条）、`diplotype`（星号型→表型，6271 条，**仅 CYP2D6/DPYD/CYP3A5**） |
| 授权 | CPIC 公开数据（引用其指南原文） |

**实测结论**：CPIC 的推荐**按临床场景分列**。同一个「CYP2C19 慢代谢 + 氯吡格雷」，ACS/PCI 场景是 **Strong**，非 ACS 场景是 **Moderate**。因此证据卡必须支持「场景」参数，否则会给出强度错误的结论。

### 2.3 数据集 C（后续可选）：NMPA 中文说明书

| 项 | 内容 |
|---|---|
| 来源 | 国家药监局说明书数据库 |
| 实测 | `nmpa.gov.cn` 返回 **412**（反爬/WAF）、页面 JS 渲染、无公开 API |
| 结论 | 暂不做爬虫。若需要，优先走「用户上传 PDF → 本地解析」（复用已有表格抽取能力）或人工整理 3–5 个关键药 |
| 价值 | 中文可读性 + 本地合规依据 + 中美标签差异比对 |

### 2.4 两个数据集的分工

```
CPIC        → 定方向：该不该用、换什么、强度多大、要不要先检测（可机读、有分级）
FDA 说明书   → 给细节：具体剂量、药代数值、警告原文、表格（可引用、可回溯）
两者对照     → 出差异：一致 / 指南更严 / 说明书更保守 / 说明书未收录
```

## 3. 技术架构

### 3.1 技术栈

| 层 | 选型 | 选型理由 |
|---|---|---|
| 环境与依赖 | **uv**（`pyproject.toml` + `uv.lock` + `.venv`），Python 3.12 | 与「电商问数」教学项目一致；锁文件可复现 |
| 分层 | `app/{api,agent,clients,conf,core,entities,models,prompt,repositories,scripts,services}` | 同上；源码与配置/提示词分离 |
| 配置 | YAML + dataclass + **OmegaConf**，密钥走 `.env` 插值 | 统一入口 `app_config.xxx`，不写死 |
| 日志 | **loguru**（文件轮转 + 控制台），参数来自 YAML | 统一日志，不再散落 print |
| 元数据库 | **MySQL 8.0**（Docker，宿主 3307） | 结构化元数据（chunk / 表格 / CPIC 表） |
| 向量库 | **Qdrant v1.16**（Docker，6333） | 语义召回；服务端与嵌入式双模式 |
| 关键词召回 | **BM25**（自实现，纯 Python） | 基因符号/等位基因/剂量词需要可控分词；2416 条规模下足够快（建索引 <1s） |
| 向量化 | **DashScope `text-embedding-v4`**（1024 维，多语言） | 中文问题直连英文语料；目标形态是 Docker 内 TEI + `bge-large-zh-v1.5`，未启动时自动降级 |
| 生成 | **DeepSeek**（OpenAI 兼容） | 逐句引用、拒答指令遵循稳定 |
| 编排 | **LangGraph** | 「证据不足直接拒答」是条件分支，用图显式表达 |
| 接口（规划） | **FastAPI** + SSE | 流式输出 + 引用高亮 |
| 前端（规划） | React + Vite + Tailwind | 同教学项目形态 |

### 3.2 数据流

```
问题/查询（药 + 基因型/表型 + 场景）
   │
   ├─ 路径 A：结构化直查（本项目的核心）
   │    MySQL: cpic_pair + cpic_recommendation + cpic_gene_result
   │    → 推荐原文 / 强度 / 检测建议 / 表型风险       ← 查表得出，不经模型
   │
   └─ 路径 B：检索（开放式问题兜底）
        说明书切片 → BM25 ∥ 向量 → RRF 融合 → 单药过滤 → 章节权威度惩罚
        → 证据分级 A/B/C/D → DeepSeek 生成（逐句 [n] 引用）
   │
   └─ 合成：证据卡（指南 / 说明书 / 一致性 / 检测建议）
```

### 3.3 数据模型（MySQL）

| 表 | 行数 | 用途 |
|---|---|---|
| `drugs` | 17 | 药物与 CPIC 期望基因 |
| `documents` | 17 | 说明书元数据（set_id、厂商、生效日期、DailyMed 链接） |
| `chunks` | 2416 | 切片（正文/表格），含 `section_priority`、`pgx_genes`、`evidence`(JSON) |

| `cpic_pair` | 50 | 基因-药对、CPIC 等级、检测建议 |

| `cpic_gene_result` | 70 | 表型解读 + EHR 风险优先级 |
| `cpic_diplotype` | 6271 | 星号型 → 表型（限 3 个基因） |

## 4. 关键设计决策（都来自实测，不是拍脑袋）

| # | 决策 | 依据 |
|---|---|---|
| 1 | 表格单独解析成行列矩阵，不按 HTML 直接切 | CYP2C19 四表型 × Cmax/IPA/VASP-PRI 的值全在表格里，切碎后无法检索也无法引用 |
| 2 | SPL 的 `<footnote>` 从单元格抽出并编号 `[n]` | 内联脚注会把脚注正文糊进表头（曾出现 `IntermediateIntermediate metabolizers…`） |
| 3 | 同一通用名多标签择优：内容丰富度分档 > 单方 > 口服 > 命中次数 > 表格数 > 日期 | 只用「任意基因命中」会把他克莫司选到 2017 年、完全不提 CYP3A5 的标签 |
| 4 | 表格分块按字符预算（含表头/脚注占用） | 只按行数切会出现 6835 字符的块 |
| 5 | 首列「行组标签」向下补全 | 切分后第二段丢失 `VASP-PRI` 参数名，检索不到 |
| 6 | 同一药物内文本指纹去重 | OpenFDA 把同一段文字放进 `use_in_specific_populations` 与 `pregnancy`，冗余 219 条 |
| 7 | 混合召回用 RRF，不用加权求和 | 余弦 0–1 与 BM25 0–∞ 量纲不同 |
| 8 | 章节权威度惩罚（黑框警告 > 临床药理 > 患者版） | 患者版说明书复述黑框警告，纯相似度会把它排第一 |
| 9 | 单药自动过滤 | 说明书互相引用（泮托拉唑标签里也提氯吡格雷），不过滤会串药 |
| 10 | 重排默认关闭 | gte-rerank 实测把 MRR 从 0.929 拉到 0.707（完整调参记录见 `reports/stage2_retrieval.md`） |
| 11 | 证据不足先判、再决定是否调模型 | D 级（无任何含目标基因的段落）直接拒答，236ms，不依赖模型是否听话 |
| 12 | 证据卡必须带「临床场景」维度 | CPIC 同一表型在 ACS/PCI 是 Strong、非 ACS 是 Moderate |
| 13 | 说明书未收录该基因时降级而非硬凑 | 辛伐他汀 + SLCO1B1：降级取该药通用肌病/剂量警告，并显式标注「不能作为基因型依据」 |

## 6. 评测方案（不需要医学背景也能验收）

### 6.1 自动指标（可写进 CI）

| 指标 | 定义 | 门槛 |
|---|---|---|
| **引用忠实度** | 每个带 `[n]` 的句子，其引用 chunk 中必须出现该句关键实体（药名/基因/剂量数字/禁用词） | ≥ 95% |
| **数字一致性** | 答案中的剂量数值必须能原样在引用 chunk 中找到 | 100%（任何不一致视为幻觉） |
| **禁用词方向** | 原文 `contraindicated` 不得被表述为「慎用」 | 100% |
| **越界引用** | `[n]` 超出证据条数 | 0 |
| **拒答正确性** | 说明书未收录基因时必须拒答/降级 | 100% |
| **CPIC 对照** | 证据卡推荐方向与 CPIC 官方行一致（方向比对，非文字比对） | ≥ 95% |

### 6.2 人工盲评（30 分钟）

- 10 条证据卡，隐去系统来源；
- 药师只需打 4 档：正确 / 部分正确 / 错误 / 危险，并指出「最不能接受的一句」；
- 产出：一份可引用的评审记录。

### 6.3 已完成的基线

- 检索：7 问 R@5 = 1.000、MRR = 0.929（混合召回）；
- 生成：7/7 通过、平均引用覆盖 90%、平均 3.3s、拒答 236ms；
- 数据：0 空块、0 重复块、0 缺失引用信息。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 仅英文标签 | 国内用户阅读门槛 | 专业侧先用英文原文（可折叠）；中文留到 NMPA 阶段 |
| CPIC 不给 CYP2C19 的「星号型→表型」 | 患者报告无法自动解析 | 专业侧由检验报告直接给表型；患者侧后置 |
| 证据卡一致性规则是关键词近似 | 可能出现误判 | 规则透明可复核 + 抽检；差异大的标记「需人工复核」 |
| CPU 环境无本地模型 | 依赖云端 embedding | 已做 TEI 双后端，容器启动即切换；索引可重建 |
| 数据更新 | 说明书与指南都会更新 | 原始快照 + `--refresh` 重建；chunk 带 `effective_date` |
| 合规 | 被当作医疗建议 | 明确定位为「证据核验工具」，输出是原文与差异，不是结论 |

## 9. 请评审人重点检查的问题

1. **场景是否真实**：药师/医生真的会在「开方前核对」和「处方点评」里用这种卡片吗？还是他们其实只看 HIS 弹窗和 UpToDate？
2. **一致性判定的价值**：「指南更严格 / 说明书未收录该基因」这类结论，对实际工作有用，还是属于「多余的第二列」？
3. **指标是否够**：第 6.1 节的自动指标能否真的防住幻觉？还缺哪一项？
4. **边界是否合理**：完全不做患者侧、且不给「换药/剂量」结论，会不会让工具显得没用？
5. **数据源选择**：先 FDA + CPIC、暂缓 NMPA，对国内场景是否可接受？

# 9 v2 更新（2026-11-10 晚）：RAG 为核心的重定位 + 首批真实评测

## 9.1 定位调整

按评审意见把定位收紧为一句话：

> **RAG 是主体产出（通俗、指令清晰、逐句可溯源的答案）；CPIC 结构化查表是「标准答案栏」，
> 用于同屏对照与自动打分，不是回答方式的替代。**

依据：只用说明书做 RAG 时，对「患者是 Intermediate Metabolizer 能不能用某药」这类问题，
**56%（48/85）会回答"说明书未定义该表型"**——因为 FDA 标签不使用 CPIC 的表型命名。
同义词扩展只能把方向一致率从 56.2% 提到 60.0%，治标不治本。
真正的解法是**把 CPIC 推荐文本也作为检索语料**（`data/corpus/cpic_chunks.jsonl`，306 条），
让 RAG 能同时引用指南原文与标签原文。

## 9.2 语料构成（v2）

| 来源 | 条数 | 说明 |
|---|---|---|
| FDA 说明书切片 | 2416 | 正文 1981 / 表格 435 |
| **CPIC 指南推荐切片** | **306** | 药 × 基因 × 表型 × 场景，`section_priority=1` |
| 合计入索引 | **2722** | Qdrant 2722 × 1024 维 + BM25 |

## 9.3 核心评测：RAG 答案 vs CPIC 标准答案

题目由 CPIC **机械生成**（药 × 基因 × 表型 × 场景，80 题），金标准取自 CPIC 推荐原文；
RAG 链路不看 CPIC 表结构，只做检索 + 生成；方向由 LLM 盲判（不提供金标准）后比对。

| 指标 | 结果 |
|---|---|
| 题量 | 80 |
| 一致 / 不一致 | **64 / 10** |
| 方向不明 | 6 |
| 拒答 | 0 |
| **方向一致率** | **86.5%** |

评测过程中修正的三类**判定噪声**（都记在 `reports/eval_gold.md`）：
1. 中文否定语义（「不是绝对禁用」）被关键词判成"避免" → 改用 LLM 盲判；
2. CPIC 的"标准剂量"写法太多（standard dose / standard dosing guidelines / no adjustment）→ 归一化词表；
3. `considering` 被当成 `consider`、`reduced ... (30-80% of standard starting dose)` 里的 standard 抢走判定 → 词边界 + 首句优先。

**残留 16 条非一致**分三类：CPIC 同一行内含多档表述（5 条）、标签与指南本身措辞不同（6 条）、HLA 多基因行歧义（5 条）。

## 10.5 留出实验：把循环性量化了（新增）

针对「金标准来源同时也进了语料」的质疑，做了对照实验：把 4 个药（氯吡格雷/硫唑嘌呤/卡马西平/苯妥英）
的 **182 条 CPIC 切片**从检索候选里剔除，再考同一批 42 题。

| 指标 | 对照组（含指南） | 留出组（剔除指南） |
|---|---|---|
| 一致 / 不一致 / 方向不明 | 31 / 4 / 7 | 13 / 11 / 18 |
| **方向一致率** | **88.6%** | **54.2%** |

**结论**：
1. 86.5%（80 题）主要是「检索 + 转述」能力，不是独立推理；
2. 剔除指南后"方向不明"从 7 涨到 18，说明系统倾向于承认"说明书未定义该表型"，而不是硬编；
3. 反向证明双源的必要性（说明书不用 CPIC 的表型命名）。

报告：`reports/eval_holdout.md`。
